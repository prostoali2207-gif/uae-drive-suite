# Evidence-led elite UX reference discovery — FleetDesk

Scope: benchmark research for materially new or uncertain operator workflows, not routine fixes. FleetDesk Rental Ops owns money and domain decisions; UX Architect owns final interaction, Product Interface Design owns presentation, QA owns release.

Canonical method: https://github.com/prostoali2207-gif/professional-ai-agents/blob/main/architect/methodology/excellence-reference-discovery.md
Read the latest upstream file when accessible; use these local steps when unavailable.

1. Define operator job and risk (payment, reconciliation, permissions, mobile/RTL). Judge task completion, error/recovery, navigation effort and accessibility. Visual prestige does not prove workflow quality.
2. Discover from independent origins: W3C/WAI and official design systems, original enterprise products/docs/live demos, direct operator observations, independent research and credible practitioner critique. Search rental/finance/admin analogues and adjacent exception-handling workflows.
3. Trace each candidate to original actual implementation, inspect relevant job and error states, record access/viewport/date. Distinguish OBSERVED LIVE, DOCUMENTED PATTERN, REPORTED OUTCOME, INFERRED and INACCESSIBLE. Marketing screenshots and awards are discovery leads, not confirmed performance.
4. Admit 3–5 complementary task-fit mechanisms or fewer if evidence is weak. Record direct original URL, observed behavior, provenance, limits and ADOPT/ADAPT/REJECT/TEST decision. Never pretend three articles repeating one source are independent confirmations.
5. Handoff to UX Architect, preserve rental and money invariants, then have UI Guard and QA observe real implementation. Record feedback and targeted improvements.
6. Stop on evidence saturation; skip wide benchmarks for labels, cosmetic edits or known local bugs. Formal qualification is not required for the practical reference-research procedure.
